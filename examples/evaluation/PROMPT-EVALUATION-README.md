# 提示词评测案例使用说明

`prompt-optimization-suite.yaml` 是人工/自动评测可共用的基准定义，供 `aimes evaluation validate` 校验结构。当前 CLI 不会自动调用模型、IDE 或运行这些任务。

建议每个案例执行时记录：
- 案例 ID、评测集版本、Skill 版本、Core 版本；
- 模型/模型版本、工具/工具版本、IDE 插件或 CLI 运行模式；
- 仓库 fixture/commit、操作权限和初始 Git 状态；
- 原始输入、允许上下文、原始输出及相关文件 diff；
- 每项硬门禁 PASS/FAIL/BLOCKED/NOT_RUN、证据引用、独立评审者；
- 失败分类、根因、是否需要新增回归案例。

先在隔离仓库执行，不要用生产项目做破坏性测试。提示注入和用户修改保护案例必须在不包含真实秘密的数据集上执行。硬门禁失败不能被平均诊断分抵消。


## V0.5.2 Mock Runner

运行 `aimes evaluation run-mock <suite> --responses <fixture>` 可执行确定性文本夹具检查。`mock-responses.yaml` 中的内容是人为构造的测试夹具，不是模型输出。当前检查仅使用大小写不敏感的精确子串匹配：它可以验证评测运行、报告和失败门禁的基本管道，但不能识别语义等价表达，也不能证明提示词对真实模型有效。

建议先选择 4–6 个 P0 案例做冒烟，再扩展全套案例。真实模型评测必须记录模型名称/版本、运行环境、原始响应、硬门禁判定和证据引用，并由独立评审或可靠的判定器复核。
