# AIMES 诊断与安全修复闭环

## 目标

`aimes repair` 将诊断结果转换成带风险说明、可选方案和执行边界的修复计划。默认只诊断和生成方案；只有显式使用 `--apply --confirm REPAIR` 才会执行安全修复。

## 1. 先诊断并查看修复选项

```powershell
aimes repair --root . --format json
```

修复计划会合并 AIMES 配置校验与只读文档/工程诊断，并通过 source 字段区分来源；相同诊断会去重。如有文件路径和行号，会一并返回，便于直接定位。

每个问题包含：

- `issue_id`、诊断代码、级别和原始信息；
- 建议标题、风险等级和根因说明；
- 一个或多个可选方案；
- 方案类型：`safe-auto`、`guided` 或 `manual`；
- 是否具备受控自动修复能力。

`safe-auto` 只表示 AIMES 有确定性、可复核的修复路径，不代表会绕过确认自动写入。

## 2. 预览后执行安全修复

如果项目已有有效的 `.aimes/config.yaml`，可复用其中的工具适配器：

```powershell
aimes repair --root . --format json
aimes repair --apply --confirm REPAIR --root . --format json
```

如果项目还没有 AIMES 配置，必须明确指定工具，避免猜测：

```powershell
aimes repair --apply --confirm REPAIR --tools codex-cli --root . --format json
```

确认词 `REPAIR` 不区分大小写。没有 `--apply` 时不会执行写入；缺少正确确认词时会拒绝执行。

## 3. 自动修复的安全边界

当前安全修复复用 AIMES 既有初始化与合并逻辑：

- 可补齐缺失的治理核心、规则入口和管理文件清单；
- 对可以证明仍是 AIMES 原样管理的文件，按既有管理规则更新；
- 已修改或归属不明确的用户文件会保留，并在冲突时生成独立候选文件；
- 不删除文件，不执行 Git reset/clean，不覆盖用户自定义规则，不执行远程发布；
- 配置无法解析或工具列表结构错误时停止，不猜测配置内容；
- 适配器未验证、文件与清单不一致等问题会给出人工/引导式选项，不会因为自动写入文件就标记为已验证。

## 4. 修复后复诊

命令会重新执行项目校验，并返回：

- 修复前的问题数量；
- 已消除的问题代码；
- 剩余问题和下一步选项；
- 初始化/合并过程中的文件操作及冲突信息。

退出码为 0 表示复诊无剩余问题且写入流程成功；若仍有未解决问题，命令会返回非零状态。请始终检查 JSON 中的 `remaining_actions` 和 `write_result`，不要只看退出码。

## 5. 诊断类型与处理策略

| 问题类型 | 默认建议 | 自动化策略 |
|---|---|---|
| 缺少配置 | 明确工具后初始化 | 需要指定工具和显式确认 |
| 缺少治理核心/规则入口 | 按现有适配器补齐缺失文件 | 可安全自动修复 |
| 缺少管理清单 | 重新生成可确认归属的清单 | 预览并按安全合并规则执行 |
| 配置无法解析 | 备份并人工检查 | 不自动覆盖 |
| 清单损坏 | 先备份、人工复核归属 | 不自动覆盖 |
| 管理文件已修改 | 保留用户修改，生成差异/候选 | 不直接重置 |
| 未知适配器或手动适配器 | 核对工具版本和原生规则加载方式 | 需人工/引导式验证 |
| 任务/交接路径缺失或越界 | 核对配置路径与项目记录格式 | 不猜测或创建记录格式 |
| .env.example 重复变量 | 比较值后人工合并 | 不自动删除任意一行 |
| 待审核候选文件 | 比较原文件与候选，批准后应用 | 不自动应用或删除 |
| Git 未跟踪文件 | 决定纳管或忽略 | 不自动执行 git add |
| Markdown 失效链接/薄入口异常 | 核对目标与治理入口契约 | 保留用户内容，人工批准 |

## 当前限制

当前版本先实现 AIMES 项目配置与管理文件的确定性修复闭环。它不会对任意 Python/TypeScript 业务代码自动生成并执行修复，也不会把 LLM 的推断直接作为可信修复。后续可以在同一安全协议上增加代码修复提案：隔离工作区、最小补丁、diff 审查、测试验证、失败回滚和审计记录。
