# AIMES V0.4：AI 开发准确度评测与回归

## 目标与边界

V0.4 提供可版本化的评测集格式、运行记录格式、结果汇总和回归比较。它不自动调用模型、IDE、Agent 或项目测试命令；真实任务的执行与独立验收仍由受控执行方完成。

## 命令

```powershell
# 校验评测集
 aimes evaluation validate examples/evaluation/suite.example.yaml

# 汇总一份已记录的评测运行
 aimes evaluation report examples/evaluation/run-record.example.json --format json --output .aimes/reports/run-report.json

# 对比基线和候选
 aimes evaluation compare .aimes/evaluation/baseline.json .aimes/evaluation/candidate.json --format json --output .aimes/reports/regression.json
```

## 运行记录要求

- 元数据应记录 `run_id`、`suite_id`、`suite_version`、模型版本、工具版本、Skill 版本和开始时间。
- 每个案例只能出现一次，状态为 `PASS`、`FAIL`、`BLOCKED` 或 `NOT_RUN`。
- 硬门禁逐项记录 `PASS`、`FAIL`、`BLOCKED` 或 `NOT_RUN`；`PASS` 案例不得包含非 PASS 门禁。
- 诊断分数使用 0 到 1 的数值范围。它们是诊断指标，不替代硬门禁。
- `PASS` 案例应提供证据引用；当前工具检查引用字段是否存在，但不会自动从可信证据库解析或验证签名。

## 回归判断

- 基线 PASS、候选非 PASS：记录状态退化。
- 硬门禁从 PASS 变为其他状态：回归报告 `ok=false`，退出码 1。
- 新增/删除案例单独列出；只有相同 `case_id` 的案例参与逐案例比较。
- 诊断维度给出平均分变化；当前不设置统一通过阈值，阈值应由项目治理责任人基于基线数据批准。

## 解释限制

评测结果只有在案例集、初始仓库状态、运行环境和评测方法足够可比时才有解释力。模型/工具/Skill 版本未记录、案例集不一致、证据缺失或环境阻塞都应在报告审查中显式处理。示例记录只展示数据格式，不是实测结论。
