# 历史兼容模块生命周期治理

## 原则

不能仅凭“来自 V0.3”就删除兼容模块。每个候选模块必须有依赖清单、公开行为、调用方证据、测试覆盖、迁移方案和弃用窗口。

## 状态

`ACTIVE` → `DEPRECATION_PROPOSED` → `DEPRECATED` → `REMOVAL_APPROVED` → `REMOVED`。每次状态转换都需要变更记录和回归结果；高风险接口应至少跨一个明确发布窗口再移除。

## 移除门槛

1. 全仓库和公开 API 调用方已检索；搜索盲区已披露。
2. 新路径覆盖旧路径的行为与数据契约。
3. 有迁移说明和可执行回归测试。
4. 版本发布说明已记录弃用/移除。
5. 无未解决的下游依赖，或已获得负责人批准。

V0.5.2 不删除任何 V0.3 兼容模块；本文件定义治理方式，不表示已完成兼容性盘点。
