# 外部工具失败与降级协议 V1.0

## 失败分类

| 类别 | 示例 | 默认策略 | 状态语义 |
|---|---|---|---|
| `TOOL_NOT_FOUND` | Git/Linter/AST 工具未安装 | 检查替代工具；无替代时做有限静态分析 | 自动检查 `NOT_RUN`，总体结论按证据降级 |
| `TIMEOUT` | 命令超过时间限制 | 最多一次受控重试；不得无限重试 | `BLOCKED` 或 `NOT_RUN`，记录超时 |
| `NONZERO_EXIT` | 命令返回非零 | 保留退出码与安全摘要，分析错误原因；不得隐去失败 | 检查 `FAIL` 或 `BLOCKED` |
| `PERMISSION_DENIED` | 权限或沙箱拒绝 | 不绕过权限、不提权；请求授权或停止 | `BLOCKED` |
| `OUTPUT_UNPARSEABLE` | JSON/YAML 无法解析 | 保留原始输出位置；最多一次格式化/重试 | `FAIL` 或 `BLOCKED` |
| `ENVIRONMENT_MISSING` | 依赖/配置缺失 | 说明前置条件和可执行替代方案 | `NOT_RUN` 或 `BLOCKED` |
| `UNKNOWN_FAILURE` | 未分类异常 | 记录脱敏错误摘要并停止自动扩大权限 | `BLOCKED` |

## 统一执行规则

1. 工具不可用不等于检查通过。
2. 静态文本分析可以作为降级证据，但必须标记方法和范围，不能替代运行时验证。
3. 重试必须有上限；仅对可能暂时性错误重试。权限拒绝、破坏性命令和未知异常不得自动重试绕过。
4. 保留命令、工具版本（可得时）、退出码、耗时、输出摘要、错误类别和结果状态；默认不记录凭证或完整敏感输出。
5. 最终报告必须区分 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`、`UNKNOWN`，不得把未执行或不可观察解释为通过。
