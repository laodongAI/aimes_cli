# AIMES 能力与验证状态矩阵

> 本文用于回答“功能是否存在、自动化测试是否通过、目标 AI 工具是否实际生效”。它不以文件存在或提示词自述替代运行时证据。状态需要随 CI 和真实工具试点更新。

## 1. 状态语义

| 状态 | 含义 | 不代表什么 |
|---|---|---|
| `IMPLEMENTED` | 代码或资产已进入仓库 | 不代表测试通过 |
| `AUTOMATED_TESTED` | 对应自动化测试在指定环境通过 | 不代表用户机器或 IDE 运行时已验证 |
| `RUNTIME_VERIFIED` | 在指定工具、版本和执行模式下观察到目标行为，且保存了证据 | 不代表其他版本或执行模式同样有效 |
| `PILOT_ACCEPTED` | 真实项目任务通过独立验收，并记录了基线与结果 | 不代表对所有项目普遍有效 |
| `NOT_RUN` | 尚未执行验证 | 不代表失败或通过 |
| `UNKNOWN` | 当前证据不足以判断 | 不允许默认折算为 PASS |
| `BLOCKED` | 因工具能力、权限或环境条件无法验证 | 不代表功能本身无效 |

## 2. 当前能力快照

以下状态根据仓库中的实现状态文档、CLI 命令契约和已有测试定义整理。自动化测试的最终结果以对应 GitHub Actions 运行记录为准；真实工具的运行时验证不得从静态文件推断。

| 能力域 | 已有能力 | 当前可确认状态 | 主要缺口 |
|---|---|---|---|
| 项目配置 | init、configure、inspect、diff、validate、doctor、status | 已实现；测试以 CI 为准 | 目标用户环境的端到端接入 |
| 安全升级 | dry-run、逐文件确认、备份、冲突候选、失败恢复尝试 | 已实现；测试以 CI 为准 | Windows 真实项目异常恢复演练 |
| 追溯与证据 | trace/evidence validate、Context Pack 与哈希复核 | 已实现；记录结构可校验 | 证据签名、可信执行来源、独立复现 |
| Skill 管理 | 注册表和引用文件结构校验 | 已实现结构校验 | Skill 运行时编排与质量效果评测 |
| 评测与回归 | 套件/运行记录校验、报告、基线对比、mock fixture 检查 | 已实现记录校验与确定性夹具检查 | 自动驱动真实模型/IDE 执行任务 |
| 工具适配 | 原生入口模板、手动适配说明、验证证据记录 | 配置生成已实现；运行时状态按工具区分 | 真实规则加载与行为遵循证据 |
| Token 优化 | 上下文预算、文件选择计划、Token 评测案例集 | 方案与案例集已存在 | 真实 usage 数据与质量非退化对照 |
| 工程治理 | task claim/release、范围校验、临时产物审计、工程指标 | 已实现部分本地检查 | 不遵守 AIMES 的外部工具无法被本地声明锁强制阻止 |
| 发布治理 | release validate、CI 测试、Windows EXE 构建/冒烟工作流 | 已有发布检查和 CI 工作流 | 当前 Release/tag/下载资产必须单独确认；不能将 CI 构建等同于正式发布 |

## 4. 评测结论要求

1. 静态文件检查不能证明运行时加载。
2. 模型声称“已完成”不能单独证明工程任务完成。
3. Mock Runner 只验证明确声明的 fixture 规则，不是语义评测。
4. Token 优化必须使用平台真实 usage 数据；没有真实数据时记录 UNKNOWN，不以字符数估算冒充 Token。
5. 候选版本必须与基线使用相同任务、环境和验收标准；硬门禁失败不能被平均分抵消。
6. 评测案例、工具版本、Skill 版本和原始证据必须能够追溯。
7. 面向发布的状态报告应明确列出未运行、阻塞、未知及已验证范围。

## 5. 后续维护

- 每次新增命令或能力时，同步更新能力域、证据要求和测试链接。
- 每次支持新工具版本时，新增独立验证记录，不覆盖历史结果。
- 不删除失败记录；修复后追加新的运行结果，并保留旧结果用于回归分析。
- 自动化测试状态由 CI 产出；运行时验证和试点验收由对应执行记录产出，不允许文档编辑者直接把状态从 UNKNOWN 改成 PASS 而没有证据。
