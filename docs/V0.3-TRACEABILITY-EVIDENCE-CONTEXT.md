# AIMES CLI V0.3.0：追溯、证据与上下文交接

## 1. 目标

把 V0.2 的单资产结构校验扩展为可检查的工程关系：需求、知识、复用决策、任务、实现、测试、发布和 Skill 均可作为追溯实体；`VERIFIED` 状态必须引用证据注册表中的 PASS 记录。

## 2. 追溯 Manifest

建议在项目中维护 `trace-manifest.yaml`，最小结构：

- `schema_version: 1`
- `project`：项目名称等识别信息
- `task`：当前交接任务 ID、标题、目标、状态
- `evidence_file`：项目根目录内的证据注册表路径
- `entities[]`：实体 `id`、`type`、`status`、`links[]`；如状态为 `VERIFIED`，还需 `evidence_refs[]`
- `context_files[]`：希望纳入交接清单的项目内文件
- `open_questions[]`、`risks[]`

链接可写成 `{target: REQ-001, relation: implements}`。当前 CLI 验证目标 ID 是否存在，不对 relation 的语义方向做自动裁决。

## 3. 证据注册表

每条证据使用唯一 `id`、`kind` 和 `result`。`command`、`test`、`build` 类型必须记录原始命令和整数 `exit_code`。可提供 `artifact_path` 以及 `sha256`；CLI 会检查路径不越出项目根目录、产物存在，并在提供哈希时比对文件内容。

重要限制：CLI 不执行 `command`，也不能单凭 YAML 字段证明证据真实。当前版本没有证据签名、CI 身份认证或防篡改时间戳。生产级 VERIFIED 应由可信 CI/执行器产出证据，并在后续版本引入来源认证。

## 4. VERIFIED 门禁

对 manifest 中 `status: VERIFIED` 的实体，校验器要求：

1. 存在 `evidence_file`，且路径位于项目根目录内。
2. 实体提供非空 `evidence_refs`。
3. 每个引用均可在证据注册表找到。
4. 被引用证据的 `result` 为 `PASS`。
5. 证据注册表本身没有结构错误。

这是一项静态证据引用门禁，不等同于复现测试，也不保证证据来源可信。

## 5. 命令示例

```powershell
aimes trace validate .aimes/trace-manifest.yaml --format json
aimes evidence validate .aimes/evidence.yaml --format json
aimes context pack .aimes/trace-manifest.yaml --output-dir .aimes/context-pack
```

校验命令只读。`context pack` 是本阶段唯一主动写入文件的命令；输出目录必须位于项目根目录内。它生成：

- `context-pack.json`：任务、实体、证据注册表引用、上下文文件 SHA-256 和大小。
- `HANDOFF.md`：任务目标、追溯实体、未决问题、风险及接续约束。

源文件不复制、不修改；输出清单不保证源文件之后仍未变化，接手方应重新核对哈希。

## 6. 已知边界

- 不自动从整个仓库扫描并发现所有实体；由项目维护 manifest。
- 不判断需求内容是否正确，也不自动批准需求。
- 不根据 PASS 自动将实体状态改为 VERIFIED。
- 不自动把上下文注入任何 IDE/Agent；交接文件由用户或工具读取。
- 尚未实现证据签名、评测集/回归报告（规划 V0.4）、真实多工具加载试点（规划 V0.5）。
