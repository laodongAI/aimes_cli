# AIMES CLI 产品需求基线 V0.1.0

## 1. 产品定位

AIMES CLI 是本地优先的跨 AI 开发工具工程治理配置与验证工具。它负责治理规则部署、适配器配置、冲突审计、规则入口检查和部署报告；不替代 Codex、Claude Code、Trae、ZCode 或 Copilot 执行软件开发任务。

## 2. 用户目标

- 在项目根目录通过 `aimes init` 交互选择工具并完成基础配置。
- 使用 `aimes configure --tools ...` 增加工具入口。
- 先预览再写入，保留现有项目规则与用户修改。
- 知道某个工具是“已生成配置”还是“已实际验证规则加载”。
- 通过统一配置和部署报告维护跨工具一致性。

## 3. 支持的工具执行上下文

1. Trae Code
2. VS Code + Codex
3. VS Code + Claude Code
4. VS Code + GitHub Copilot
5. ZCode
6. QCode
7. Claude Code CLI
8. Codex CLI

这里的“8 个上下文”不是 8 套治理核心。VS Code 插件与独立 CLI 可以共享对应的原生规则入口，但必须分别验证实际运行模式。

## 4. MVP 功能范围

- 初始化、增量配置、项目检查、变更预览、规则配置验证、环境诊断、状态摘要。
- 交互式工具选择和 CLI 参数选择。
- 统一治理核心的项目级部署。
- 原生工具入口模板（仅对有明确入口契约的工具生成）。
- ZCode / QCode 人工适配说明。
- 配置 Schema、受管文件 manifest、哈希审计。
- 单元测试与 JSON 输出。

## 5. 安全要求

- 默认项目级部署。
- 未经确认不覆盖已有文件。
- 发现已有文件冲突时保留原文件，将候选版本写入 `.aimes/proposed/`。
- 不执行任意 shell 命令，不删除文件。
- 不推断工具扩展已安装或规则已加载。
- 不在缺乏证据时把工具能力标记为已验证。
- 只对 manifest 证明未被用户修改的 AIMES 管理文件执行安全更新。

## 6. 非功能要求

- Windows PowerShell、macOS/Linux shell 均可运行。
- Python 3.10+；本地 YAML 解析依赖 PyYAML。
- 无云端服务依赖。
- 输出必须包含工具选择、配置动作、冲突、警告与验证状态。
- 同一目录重复执行必须幂等，不能重复追加同一工具或重复创建文件。

## 7. 暂不纳入 MVP

全局安装、自动卸载、三方合并、回滚、动态插件下载、LLM 路由、运行时规则注入、执行项目构建命令、任务/追溯全量管理、自动清理临时文件。
