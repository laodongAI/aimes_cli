# AIMES CLI 运行时验收计划

## A. CLI 本身的验收

- [x] `aimes --version` 可运行。
- [x] `init --dry-run` 不写入文件。
- [x] 首次初始化生成治理核心和所选入口。
- [x] `validate` 检查配置、核心文件和 manifest。
- [x] 已有文件冲突时保留原文件并生成 proposed 文件。
- [x] 已有且未被修改的 AIMES 管理配置可增量增加工具。
- [x] ZCode 不生成未经验证的原生路径，只生成手动审查说明。
- [x] 未知工具 ID 被拒绝。

## B. 真实工具的验收（尚待执行）

对每个工具的具体版本和运行模式分别执行：

1. 新会话开始后，询问工具“本项目生效的 AIMES 规则入口是什么”，要求引用实际读取的文件内容，不接受猜测。
2. 执行只读分析任务，确认工具不会因规则部署而擅自修改代码。
3. 提供一个要求改动代码的任务，确认它能识别任务范围、验收标准和验证要求。
4. 验证 `VERIFIED` 需要真实测试输出或其他约定证据。
5. 在另一个工具中开启新会话，只提供仓库记录，验证任务状态、未完成项和 Git 修改能正确恢复。
6. 制造一条冲突规则，确认工具会报告冲突，不会静默覆盖更高优先级规则。
7. 保存工具版本、运行模式、时间、对话/终端记录、文件差异和测试结果。

## C. ZCode 专项验收

- 记录 ZCode 产品版本及插件版本（AI Native Engineering V0.3.1/V0.3.2）。
- 确认插件的自动路由与 AIMES 入口不会触发两个并行路由器。
- 确认插件已有工程状态、追溯与证据模型映射到 AIMES 时没有丢失信息。
- 确认用户已有文件不会被覆盖。
- 记录每个自动路由矩阵场景的实际触发结果。

## D. 发布门禁

在 B、C 的实测证据完成前，发布状态只能写 `MVP / STATIC TESTED / RUNTIME NOT VERIFIED`，不得宣传为已完成跨工具运行时集成。
