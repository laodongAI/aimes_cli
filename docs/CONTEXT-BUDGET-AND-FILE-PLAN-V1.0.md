# 上下文预算与文件选择计划 V1.0

## 目的

把“最小充分上下文”转化为可执行、可复核的文件选择策略。该协议是提示词约束；除非运行时明确支持文件访问拦截，否则计划本身不构成技术层面的访问控制。

## 默认预算

- 初始探索：最多 8 个文件或 120 KB 文本，以先达到者为准。
- 扩展读取：只有当已有证据不足以回答关键问题时，记录缺口和理由后才扩展；每轮增加最多 8 个文件或 120 KB。
- 大文件：先查看目录、标题、符号索引或相关片段，不默认读取全文。
- 机密文件、凭证、私钥、Cookie、token：不得为了普通代码理解而读取或复制；若任务确需处理，必须说明必要性并遵守授权流程。
- 二进制、生成物、依赖缓存和 vendor：除非问题明确涉及，否则排除。

## 计划字段

每个计划必须包括 `task`、`budget`、`files`、`exclusions`、`unresolved_questions`。每个文件条目包含 `path`、`priority`、`reason` 和 `expected_evidence`。

## 执行策略

1. 先读取项目说明、目录索引和相关规则入口。
2. 生成文件选择计划，标出高置信直接证据与可能的间接依赖。
3. 低风险、只读且未超预算：可自动继续；高风险文件、敏感路径、超预算或会触发写入：先请求确认或按工具权限阻断。
4. 每轮读取后记录实际读取清单、排除项和未覆盖区域。
5. 若证据不足，优先说明缺口，再按预算分轮扩展。

## 禁止行为

- 声称“已检查整个仓库”，除非确实完整检查并有可复核依据。
- 将计划中的文件描述为已读取。
- 因为搜索未命中就断言不存在。
- 将预算规则当作工具层权限控制的替代品。
