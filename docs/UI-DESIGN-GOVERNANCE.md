# AIMES UI 设计能力治理与调用规范

## 1. 目标

本规范把 UI 设计从“可选建议”变为可路由、可执行、可验证、可评测的工程能力。能力来源可参考 Anthropic Frontend Design、Vercel Agent Skills / Web Design Guidelines、Material Design 及 WCAG，但项目批准规范优先；第三方内容应吸收方法，不直接整包复制。

## 2. Skill 调用路由

| 任务特征 | 必须优先调用 | 其他适用能力 |
|---|---|---|
| 新建页面、仪表盘、复杂布局、主要页面重设计 | `frontend-design` | `design-system-governance`、`ui-quality-review`、`ui-implementation-validation` |
| 设计 Token、主题、组件库、公共组件契约 | `design-system-governance` | `ui-quality-review`、`ui-implementation-validation` |
| 页面审查、样式小改、UI Bug、表单或导航调整 | `ui-quality-review` | `ui-implementation-validation`（改动后） |
| 响应式、键盘/焦点、可访问性、视觉回归或前端验收 | `ui-implementation-validation` | `ui-quality-review`（发现问题或需要修复时） |
| 纯后端且不影响用户可见行为 | 不触发 UI Skills | 如出现用户可见影响，再按路由触发 |

### 2.1 调用要求

1. AI 工具应在任务分析阶段匹配 `skills/registry.yaml` 的 `triggers`，并读取对应 `file`；不得只复述 Skill 名称。
2. 新建/重设计任务先做设计简报与视觉方向；公共设计系统变更先盘点资产并提出影响分析；页面改动后调用验证 Skill。
3. 简单局部修复不强制完整设计流程，但仍必须遵守 Core 的范围保护、项目规范优先和证据真实性。
4. 当工具无法访问 Skill 文件时，必须明确报告加载失败，并按 Core 中的 UI 最低规则降级执行；不能宣称 Skill 已调用。
5. 同一任务可以组合多个 Skill，但应复用已产生的基线/发现，避免重复读取和重复输出。
6. 每次实际运行可在任务记录中标注 Skill ID、版本、输入、输出、执行步骤、检查状态和证据引用；注册表存在本身不证明真实工具已加载。

## 3. 设计系统基线

- 项目已批准的品牌、设计 Token、组件契约和产品决策优先于通用建议。
- 没有既有系统时，先形成候选设计简报与 Token，记录为“建议/待批准”，不把模型偏好伪装成项目标准。
- 设计 Token 应使用语义化名称，集中管理颜色、字体、字号、间距、尺寸、圆角、阴影、层级、动效与断点；不在页面中散布重复硬编码值。
- 优先复用现有组件；公共组件 API、全局主题、品牌资产或依赖升级属于高影响变更，应先给出影响范围、兼容性、迁移和回滚方案。
- 页面设计应先明确目标用户、核心任务、信息层级和主行动，再选择布局和视觉风格；避免无理由套用通用模板。
- 交互状态按适用性覆盖默认、悬停、焦点、禁用、加载、空、成功、错误、无权限和只读状态。

## 4. UX、响应式与无障碍最低要求

- 所有关键流程必须可理解、可操作、有反馈；表单要有清晰标签、字段级错误、错误关联和提交状态。
- 检查语义结构、可访问名称、键盘可达、焦点可见、颜色对比、缩放、触控目标和内容溢出。
- 以项目明确声明的目标标准为准；未声明时可将 WCAG 2.2 AA 作为评审参考基线，但不得宣称认证或合规保证。
- 响应式检查应记录实际验证的视口、浏览器和页面状态；没有实际验证时标记 `NOT_RUN`、`BLOCKED` 或 `UNKNOWN`。
- 自动化无障碍扫描、静态检查、构建、浏览器交互、截图对比和人工验收是不同证据类型，不可互相替代。

## 5. UI 交付质量门禁

交付报告必须包含：
- 规范基线与来源；
- 页面/组件/视口/交互状态范围；
- 发现项、严重性、证据、影响与复现条件；
- 变更文件/组件及范围保护说明；
- 实际执行的测试、构建、浏览器/截图/无障碍检查；
- 未执行项、阻塞、剩余风险和后续步骤。

PASS 只用于实际执行且满足预先定义判据的检查。工具不可用时应给出替代步骤，不得伪造浏览器、截图、扫描或人工验收结果。

## 6. 评测与持续改进

固定回归集位于 `examples/evaluation/ui-quality-governance-suite.yaml`。每次重大规则/Skill 调整应校验套件结构，并在隔离项目中对真实 AI 工具运行案例，保留原始输出、diff、命令结果和独立评审。当前案例集定义不代表已在所有 IDE/CLI 中运行通过。

建议评测指标包括：
- Skill 触发准确率与遗漏率；
- 项目设计系统复用率；
- 任务范围外变更数；
- 验证证据完整率与伪通过数；
- 响应式/键盘/表单状态覆盖率；
- UI 缺陷首次发现率与修复后回归率；
- 在硬门禁不退化前提下的上下文与 Token 使用变化。

## 7. 第三方材料纳入原则

参考材料：
- Anthropic Frontend Design：强调有意图的视觉方向和可用于生产的界面实现。
- Vercel Agent Skills / Web Design Guidelines：提供前端最佳实践和可访问性、交互、性能等审查维度。
- Material Design：可作为设计系统组织方式参考。
- WCAG 2.2：可访问性要求的规范性参考。

采用前应检查许可证、版本、来源、重复度和跨工具兼容性。AIMES 自有 Skill 必须包含触发条件、输入、前置条件、步骤、输出契约、权限、安全、失败处理、完成判据和评测案例；不以下载或安装第三方 Skill 代替规则路由集成。
