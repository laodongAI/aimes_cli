# AIMES V1.3 设计基线包

- **包版本**：0.1.0-draft
- **设计状态**：待评审；尚未作为正式规范发布
- **基线规范**：AIMES-SPEC-001 V1.2（原文随包提供）
- **本阶段目标**：先统一设计和能力契约，再进入 CLI / Skills 实现

## 本包解决什么问题

本包将两项新增核心能力纳入 AIMES 治理：

1. **需求认知工程**：帮助 AI 从自然语言形成可审查、可追溯、可验收的需求模型，并在关键歧义未解决时停止受影响的写操作。
2. **项目知识复用工程**：帮助 AI 发现已有实现与经验，判断复用适用性，迁移模式并验证结果，避免重复开发和机械套用。

同时定义 Skill 生命周期、评测框架和 CLI 增量实现边界。它是设计包，不代表这些能力已经实现或已在 ZCode、Codex、Claude Code 等工具中验证。

## 核心设计原则

- V1.2 是当前治理基线；V1.3 文件在评审批准前属于提案。
- 不另造一套状态词表。沿用 V1.2 的 `DRAFT`、`APPROVED`、`PLANNED`、`IN_PROGRESS`、`IMPLEMENTED_UNVERIFIED`、`VERIFIED`、`FAILED`、`BLOCKED`、`REJECTED`、`DEPRECATED`、`REMOVED`、`UNKNOWN`、`NOT_APPLICABLE`。
- 需求审批状态与实现验证状态分开管理，不把它们混为一个状态字段。
- 不因新能力而重复建立权威文档、ID、追溯注册表或项目事实源。
- 模型生成的需求解释、知识总结和方案建议默认是候选内容；批准与验证必须有明确证据。
- Skills 是工作流程封装，不是新的治理事实源；CLI 是检查与证据工具，不替代模型的业务分析，也不自动审批。
- 未经实际工具试点，不声称规则已加载或 Skill 已生效。

## 建议使用顺序

1. 审查 `01`，确认新增能力边界与 V1.2 兼容原则。
2. 审查 `02`、`03`，确认两项核心能力的工作流和数据契约。
3. 审查 `04`、`05`，确认 Skill 生命周期和评测方法。
4. 审查 `06`、`07`，再确定 CLI 与 Skills 实现任务。
5. 在 `08` 中逐项记录决策；批准后再将提案融合为正式 V1.3，并启动实现。

## 明确的非目标

本包不修改任何业务项目代码；不自动修改原 V1.2 规范；不声明所有 AI 工具具备相同规则入口；不将模型自评当作验证证据；不承诺一次性实现全套 RAG、图数据库或自治 Agent。
