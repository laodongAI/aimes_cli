# AIMES 项目知识复用工程规范（提案）

- **文档编号**：AIMES-PKR-1301
- **状态**：DRAFT / 待评审
- **目标**：降低重复开发，提升项目内复用正确性和跨场景知识迁移能力。

## 1. 定义

- **检索**：找到可能相关的代码、文档、决策、测试或历史任务。
- **复用**：直接使用已存在且适用的资产。
- **适配**：在保留既有设计/接口的基础上调整资产以满足新场景。
- **模式迁移**：提炼旧方案的原理，在新上下文中重新设计具体实现。
- **经验沉淀**：把已验证、具有后续价值的知识作为候选资产记录，并经过规定门禁后提升成熟度。

检索命中不等于复用正确；代码相似度不等于业务适用性；历史成功也不保证在新版本/新约束下继续成立。

## 2. 项目知识资产范围

1. **实现资产**：公共函数、组件、服务、API、配置、脚本、测试、Schema。
2. **结构资产**：模块职责、调用图、数据流、依赖图、插件注册与动态加载机制。
3. **业务/设计资产**：业务规则、领域模型、接口契约、ADR、设计模式与选型原因。
4. **任务/经验资产**：历史任务、缺陷根因、修复 diff、回归测试、已知限制和失败案例。
5. **工程模式**：在多个案例或明确权威设计中验证过的解决策略、模板和 Skills。

项目可以先从现有文档、Git、代码搜索和测试入手，不要求立即建设向量数据库或知识图谱。

## 3. 检索策略

每项新功能/缺陷任务至少按风险和复杂度选择适当检索范围：

- 先读任务、相关需求、项目规则和文档索引；
- 搜索已有模块、公共组件、同类 API、测试和调用方；
- 查阅相关 ADR、历史缺陷和近期变更；
- 对可能复用的资产验证文件、符号、版本和实际引用；
- 记录查询范围和已检查位置，避免将有限搜索误称为全库穷尽。

对高风险任务，检索结果应覆盖代码、设计、测试和相关历史问题；轻量任务可缩小范围，但必须说明范围。

## 4. 复用决策模型

每个有实质影响的复用决策应比较：

| 维度 | 必须回答的问题 |
|---|---|
| 业务目的 | 原资产和新任务是否解决相同或兼容的问题？ |
| 前置条件 | 原方案依赖的状态、输入、权限和环境是否成立？ |
| 架构契约 | 模块边界、接口、数据模型和依赖是否兼容？ |
| 非功能约束 | 安全、性能、并发、可观测性和维护成本是否满足？ |
| 版本有效性 | 原资产是否仍有效，是否存在后续替代或已知缺陷？ |
| 例外与反例 | 哪些情况不适用，旧方案有哪些失败案例？ |
| 验证方法 | 哪些测试能证明新场景下正确？ |

决策结果只能从以下局部枚举选择：`REUSE`、`ADAPT`、`TRANSFER_PATTERN`、`DO_NOT_REUSE`、`NEED_MORE_EVIDENCE`。该字段描述决策类型，不是 AIMES 通用状态值。

该 Schema 是提案；正式字段和状态须在批准后纳入唯一机器契约。引用必须指向真实资产，不能填入模型编造的路径或 ID。

## 6. 知识资产卡片

建议知识资产最少记录：

- `knowledge_id`、标题、类型和简短摘要；
- 来源引用、产生任务和基线 commit/版本；
- 适用条件、约束、例外和失效条件；
- 验证案例/证据、已知缺陷和反例；
- 维护责任/最后复核时间；
- 生命周期成熟度；
- 关联模块、需求、设计、代码、测试和 Skill。

成熟度建议为：

- `candidate`：模型/开发者提出，尚未验证；
- `reviewed`：已完成来源和适用性审查；
- `validated`：有真实验证证据或批准的权威依据；
- `deprecated`：不再推荐使用，记录原因和替代项。

这是知识生命周期字段，不得替代 V1.2 全局状态词表。资产成熟度必须能追溯到证据，不应仅由模型自评决定。

## 7. “搜索—比较—迁移—验证—沉淀”流程

1. **搜索**：查找实现、接口、设计、测试、缺陷和历史任务。
2. **比较**：明确相同点、差异、前置条件、约束冲突和未知项。
3. **决策**：选择直接复用、适配、迁移模式、不复用或补充证据。
4. **计划**：说明改动范围、回归影响、失败处理和验证策略。
5. **实施**：遵守 AIMES 单写入者、最小变更、用户修改保护和审批边界。
6. **验证**：运行需求验收、回归、契约和适用的非功能检查。
7. **沉淀**：只有有价值的经验才创建候选知识；记录来源、适用条件、反例和验证结果。
8. **复核**：当代码、依赖或架构变化时，检查知识资产是否过期或被替代。

## 8. 举一反三的推理契约

AI 在迁移旧方案时，必须输出：

- 从旧案例提炼的通用原理；
- 原案例成立的条件；
- 当前案例与原案例的关键差异；
- 哪些部分可以复用，哪些必须调整；
- 可能失效的假设；
- 能够证伪方案的测试或检查；
- 如果迁移失败，如何回退或采用替代方案。

若无法说明原理和适用条件，只能报告“发现候选相似资产”，不能宣称已完成举一反三或直接照搬。

## 9. 经验沉淀门禁

适合沉淀的内容：稳定业务规则、通用缺陷根因、经验证修复模式、公共接口用法、重要反例、可复用测试、可复用 Skill 改进。

不应直接沉淀为权威知识的内容：未经验证的模型总结、单次偶然现象、无来源推断、复制来的外部建议、临时 workaround（除非明确标记为临时且有期限）。

候选知识至少经过去重、来源核验、适用条件检查和验证/评审，再决定是否升级成熟度。

## 10. 指标建议

- 相关资产检索召回率（通过标注评测集衡量，而非搜索结果数量）；
- 复用决策正确率；
- 重复实现率；
- 迁移后独立验证通过率；
- 同类缺陷复发率；
- 过期知识命中率/误用率；
- 知识来源可追溯率。

指标必须同时报告样本量、扫描范围、排除项和置信限制。不要以“复用次数越多越好”为目标；错误复用应被视为负面结果。
