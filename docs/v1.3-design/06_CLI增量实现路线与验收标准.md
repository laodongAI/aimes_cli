# AIMES CLI 增量实现路线与验收标准

- **文档编号**：AIMES-CLI-1301
- **状态**：DRAFT / 待评审
- **实现基线**：AIMES CLI V0.1.0（已有原型；新能力均需实际代码审计和测试后再确认）

## 1. CLI 的责任边界

CLI 负责可重复、可解释、可机器检查的治理动作：配置和注册表校验、ID/引用/路径检查、上下文包元数据、证据记录、评测案例管理、报告生成和退出码。

CLI 不负责替代模型完成业务理解，也不自动批准需求、决定架构、判断所有复用是否正确或将候选知识自动升级为权威。涉及语义判断时，CLI 可以要求记录决策与证据，并将结果交给人工或 AI 工作流审查。

## 2. 先审计 V0.1.0，再新增命令

实施前必须：

1. 在真实仓库/构建产物中审计当前 V0.1.0 的源码、测试、命令和限制；
2. 确认已有 `init/configure/inspect/diff/validate/doctor/status` 的真实行为；
3. 复核配置 Schema、项目路径、生成文件覆盖保护和 manifest 机制；
4. 记录单元测试、打包测试、Windows 安装和目标工具试点的状态；
5. 不因为历史交付说明存在就假定目标环境验证已通过。

## 3. 建议增量版本

### V0.2：结构化需求/知识/Skill 契约

建议能力：
- 注册表 Schema 校验；
- 需求认知记录的必需字段、引用和状态校验；
- 知识资产来源引用、适用条件和成熟度字段校验；
- Skill 注册表和文件 ID 对齐检查；
- 检查重复 ID、无效引用、重复权威来源和未知字段；
- 输出 JSON + 人类可读报告。

不做：AI 自动评审、自动批准需求、自动从任意代码推断完整依赖图。

### V0.3：追溯、复用决策和证据关联

建议能力：
- 复用决策记录引用检查；
- 需求—设计—实现—测试关联缺口检查；
- 验证证据元数据检查（命令、结果、时间、commit、范围、证据路径）；
- 检查 `VERIFIED` 是否缺少规定证据；
- 基于配置生成上下文包索引和交接摘要；
- 所有检查默认只读，不自动改写权威需求。

### V0.4：评测集和回归报告

建议能力：
- 评测案例 Schema/ID/版本校验；
- 评测运行元数据和结果归档；
- 基线对比、硬门禁失败汇总和指标计算；
- 保留原始结果和失败案例；
- 支持 CI 以退出码阻断明确的契约/硬门禁错误。

不负责生成模型质量的绝对分数，不将单一综合分作为发布批准。

### V0.5：工具执行证据与交接试点

建议能力：
- 记录实际工具/版本/模式/规则入口和试点证据；
- 交接包一致性检查；
- 规则加载试验的记录模板和结果核验；
- 多工具任务交接的验收报告。

不得把文件存在视为规则加载成功；规则加载仍需实际行为测试。

## 4. 建议的命令契约（待批准）

```text
aimes requirement validate <path> [--format text|json]
aimes knowledge validate <path> [--format text|json]
aimes reuse validate <path> [--format text|json]
aimes skill validate [<id>|--all] [--format text|json]
aimes eval validate <suite-path> [--format text|json]
aimes eval report <run-path> [--baseline <run-path>] [--format text|json]
aimes evidence validate <path> [--format text|json]
```

这些是候选命令名，不代表已实现。正式命令必须与现有 CLI 的参数风格、退出码、JSON Schema、错误级别和配置机制保持一致。

## 5. 退出码建议

应先盘点 V0.1.0 是否已有稳定退出码契约。若无，则在 V0.2 统一定义，例如：`0` 通过、`1` 发现治理错误、`2` 配置/输入错误、`3` 环境/依赖阻塞、`4` 内部执行错误。该映射只是建议，不能未经兼容性评估直接改变现有命令行为。

## 6. 安全要求

- 默认只读；任何修复/写入命令必须显式选择并提供预览。
- 所有路径规范化后确认位于允许范围；防止路径穿越和符号链接逃逸。
- 验证命令必须由项目配置白名单提供，以参数数组执行，不拼接不可信 shell 字符串。
- 不存储明文密钥、凭证或不必要的敏感上下文。
- 报告中对秘密做脱敏。
- 对未知 Schema 字段按配置警告或失败；不能静默忽略影响安全/状态的未知字段。
- 任何自动写入不得覆盖用户修改；优先生成 proposed/staged 内容供审查。

## 7. 每阶段验收

### V0.2
- 正常、缺字段、错误状态、重复 ID、失效引用和路径穿越测试覆盖；
- 所有检查有确定性输出和非零退出码语义；
- 不修改被检查的源文件；
- JSON 输出有版本化 Schema。

### V0.3
- 能识别至少一种断开的需求追溯关系；
- 能识别缺少证据的 `VERIFIED` 记录；
- 不能仅凭文件存在把工具能力标为 `VERIFIED`；
- 上下文包标记基线 commit、生成时间和来源。

### V0.4
- 固定评测集可重复运行；
- 报告包含模型/工具/Skill 版本、样本量、硬门禁失败和失败案例；
- 基线对比不会隐藏未运行/阻塞案例；
- 回归测试覆盖评测工具本身。

### V0.5
- 至少一个 IDE/Agent 与一个 CLI 形态工具完成受控接力试点；
- 实际规则加载和交接恢复有证据；
- 用户未提交修改保留；
- 工具能力未知时明确降级。

## 8. 实施原则

先完善 Schema、校验和只读报告，再引入写操作；先以一个真实项目试点，不一次支持所有工具；每次版本发布必须提供源码、测试、构建产物、变更记录和已知限制。版本完成的定义是“达到本阶段验收标准”，不是“命令能运行”。
