# AIMES 现有项目安全升级流程

## 目标与边界

`aimes upgrade` 用于将**当前已安装的 AIMES CLI 所携带的治理模板**升级到现有项目。它不负责自动下载/安装新的 CLI 程序；CLI 程序本身的安装升级仍按所采用的 Python 包或 EXE 发布方式执行。命令会显示已安装 CLI 版本和项目清单记录的版本。

## 推荐操作

在目标项目根目录执行：

```powershell
# 只读预览：检查版本并列出新增、可安全更新、未变化及冲突文件
aimes upgrade

# 交互式逐项升级：每个文件分别确认，最后输入 UPGRADE
aimes
# 在主菜单选择“升级现有项目 AIMES”

# 非交互执行：仅在检查过预览后使用
aimes upgrade --apply --confirm UPGRADE

# 升级后验证
aimes validate
aimes inspect
```

## 文件处理策略

| 分类 | 默认行为 |
|---|---|
| 新文件 | 仅在用户选择后新增 |
| AIMES 清单证明未被修改的托管文件 | 备份后更新 |
| 内容与目标模板一致的文件 | 保持不变 |
| 无清单记录、哈希不匹配或疑似项目自定义的文件 | 原文件不覆盖；可生成候选文件供人工合并 |
| 路径对应目录、无法读取的文件 | 标记冲突并跳过 |
| 不在本次升级计划中的业务源码、测试数据和项目文档 | 不触碰、不删除 |

现有文件的安全更新依赖 `.aimes/manifest.json` 中的哈希记录。没有有效清单时，升级器不会猜测哪些文件可以覆盖。冲突候选文件写入 `.aimes/proposed-upgrade/`；升级前已有文件的备份写入 `.aimes/backups/upgrades/<UTC 时间戳>/`。

## 版本解释

- **已安装 CLI 版本**：运行中的 AIMES CLI 代码版本。
- **项目 CLI 版本**：项目清单上一次记录的 CLI 版本；它不一定等于项目当前实际使用的 EXE/包版本。
- **治理目标版本**：当前 CLI 所携带的治理核心版本。

此功能只比较本地已安装版本与项目清单，不会联网查询 GitHub 最新发行版。升级前请确保当前 CLI 已更新到你希望部署的版本。

## 安全限制

- 预览不写入项目文件。
- 升级不删除任何项目文件。
- 修改前备份将被覆盖的现有文件。
- 自定义文件只提供候选版本，不自动合并。
- 如果写入中途出现错误，先查看输出中的备份目录与错误清单，不要直接重复执行；完成后运行验证命令并审阅差异。
