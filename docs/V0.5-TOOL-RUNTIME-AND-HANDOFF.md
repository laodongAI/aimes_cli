# V0.5.0 工具运行时验证与交接完整性

## 目标

将“工具入口已配置”与“运行时已加载规则”明确分离。AIMES CLI 不通过猜测可执行文件或静态文件存在性宣称规则加载成功；运行时证据由使用者在目标产品和版本中采集，再由 CLI 进行结构、证据字段和哈希一致性检查。

## 证据记录

`examples/adapters/verification-evidence.example.yaml` 展示 `checks` 记录。每条记录至少需要唯一 `id`、受支持的 `tool`、`verification` 和 `method`。推荐补齐 `product_version`、`rule_entry`、`observed_at`、`observer`。

- `NOT_RUN`：尚未执行验证。
- `UNKNOWN`：当前证据不足以判断。
- `BLOCKED`：因环境或权限等原因无法完成。
- `FAIL`：已执行检查，结果不符合预期。
- `PASS`：有足够证据支持检查通过。

`file_inspection` 不能单独用于 PASS。PASS 的方法必须为 `runtime_observation`、`automated_check` 或 `user_confirmed`，并记录 `artifact_path` 或 `evidence_note`。这属于一致性门禁，不是不可伪造的证明。

## 交接完整性

Context Pack 保存源文件相对路径、SHA-256 和大小，不复制项目源文件。接手者运行 `aimes context validate`，若文件缺失、哈希变化或路径越界，CLI 会报告错误。哈希变化只说明源内容不同，不代表变化一定有问题；应重新审阅并重新生成交接包。

## 推荐试点

1. 选择一个无敏感数据的测试仓库和固定分支。
2. 分别对 VS Code + Codex、VS Code + Claude Code、对应 CLI 执行独立验证；不要因共享规则文件而合并结果。
3. 使用专门的可辨识规则探针，要求工具输出指定标记并遵守一条无副作用的约束。
4. 保存工具版本、提示词、完整输出、时间和规则入口；避免把账号、令牌、个人数据放入证据。
5. 新会话或切换工具后复测，并把结果登记到证据文件。
6. 生成 Context Pack，模拟源文件变化后验证其能够发现哈希不一致。

## 非目标

本版本不读取 IDE 私有运行状态、不自动向工具注入探针、不自动操作 GUI、不签名证据、不证明记录的观察者身份，也不自动将 Skills 升级为 VERIFIED。
