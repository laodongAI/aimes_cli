# Skill：需求认知工程

## 目标与边界
将自然语言需求转化为可确认、可设计、可实施、可测试、可追溯的结构化需求；识别缺口、冲突和不可判定的验收条件。本 Skill 不批准需求、架构决策或发布状态。

## 触发条件
新功能、需求变更、需求歧义、范围讨论、验收标准审查、产品行为变更。

## 必需输入
- 任务目标与需求来源；缺失时标记 UNKNOWN 并列出影响。
- 项目上下文与权威规则；写操作前检查工作区并保护用户修改。
- 相关需求、业务规则、架构/ADR、接口/数据契约和测试，按任务适用性读取。

## 工作流程
1. 还原业务问题、目标用户、触发条件、主流程、输入输出、异常结果、非目标和价值；不要把方案当作需求事实。
2. 定位权威来源，记录实际读取路径及冲突；代码只说明现状，不自动证明需求正确。
3. 拆分业务目标、功能/非功能需求、约束、依赖和稳定 ID；区分明确陈述、权威事实、推断、候选假设与未知。
4. 按适用性检查权限、安全、数据完整性、状态转换、边界值、异常、幂等、并发、重试/超时、兼容性、性能、可观察性、部署恢复与可访问性。
5. 对歧义记录影响、后果、阻断级别、可选解释和建议澄清问题；优先澄清会改变实现、安全或验收结果的问题。
6. 为关键需求定义可观察行为、条件/输入、预期结果与判定方法。不得自行编造性能阈值。
7. 检查来源可追溯性、可测试性、未解决冲突与未经批准假设；只有责任人批准证据才能标记 APPROVED。
8. 输出需求基线、追溯关系、待确认问题，以及可继续的只读分析和必须等待确认的写操作。

## 必需输出
- requirement_cognition_record：目标、范围/非范围、角色与场景、需求项、约束、依赖、来源、验收标准。
- open_questions：问题、影响、阻断级别、选项、推荐澄清问题与责任人。
- review_report：覆盖检查、缺口、风险、冲突、可判定性和检索盲区。
- approval_gates：待批准事项、批准依据及未批准时允许/禁止的动作。

## 停止与降级
关键需求冲突、安全权限不明或验收结果随解释改变时，停止受影响的写操作并提出澄清。非阻断未知项可在显式标注假设下继续只读分析。权限/审批缺失标记 BLOCKED；未执行检查标记 NOT_RUN；证据不足标记 UNKNOWN。宿主级 Skill 的降级执行不能冒充 AIMES 项目 Skill 调用。

## 完成判据
关键结论有来源；事实、推断、假设、未知与冲突区分清楚；输出契约完整；失败、未执行项、风险与下一步明确；完成状态不高于证据支持的状态。
