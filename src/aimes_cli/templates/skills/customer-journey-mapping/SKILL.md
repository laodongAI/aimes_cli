# Skill: 客户旅程映射 (Customer Journey Mapping)

## Purpose / 目的与价值主张

基于客户旅程映射 (Customer Journey Mapping, CJM) 方法论，系统性地分析和可视化客户与产品的互动全流程。帮助产品团队深入理解客户体验，识别痛点和机会，优化客户旅程以提升满意度和转化率。

**核心价值**:
- 从客户角度理解产品体验
- 识别客户旅程中的关键痛点和机会
- 提供可视化的客户体验分析工具
- 支持数据驱动的产品改进

## Input / 输入要求

**最佳输入**: 产品名称、目标客户群体、需要分析的客户旅程
**有用补充**: 客户反馈、使用数据、竞品分析、团队假设

**示例调用**: `为 AIMES CLI 创建客户旅程映射，分析新用户从安装到首次成功使用的完整流程`

## Key Concepts / 核心概念

### 客户旅程映射框架

客户旅程映射是一种可视化工具，帮助产品团队：

1. **定义客户角色**: 明确目标客户的特征和需求
2. **描述旅程阶段**: 将客户与产品的互动分为不同的阶段
3. **分析每个阶段**: 在每个阶段中识别客户的行为、想法、感受和痛点
4. **识别机会**: 基于分析结果识别改进机会

### 核心组件

#### 1. 客户角色 (Persona)
- **定义**: 目标客户的典型代表
- **特征**: 人口统计、行为特征、需求、目标
- **示例**: "工程团队负责人，拥有 50+ 工程师，关注工程质量和治理"

#### 2. 旅程阶段 (Journey Stages)
- **定义**: 客户与产品互动的不同阶段
- **常见阶段**: 
  - **认知** (Awareness): 客户了解产品
  - **考虑** (Consideration): 客户评估产品
  - **决策** (Decision): 客户决定使用产品
  - **采用** (Adoption): 客户开始使用产品
  - **保留** (Retention): 客户持续使用产品
  - **推荐** (Advocacy): 客户推荐产品

#### 3. 客户行为 (Customer Actions)
- **定义**: 客户在每个阶段中的具体行为
- **示例**: "搜索产品信息"、"下载安装包"、"阅读文档"

#### 4. 客户想法 (Customer Thoughts)
- **定义**: 客户在每个阶段中的想法和问题
- **示例**: "这个产品能解决我的问题吗？"、"安装过程会复杂吗？"

#### 5. 客户感受 (Customer Feelings)
- **定义**: 客户在每个阶段中的情感状态
- **示例**: "好奇"、"焦虑"、"满意"、"失望"

#### 6. 痛点 (Pain Points)
- **定义**: 客户在旅程中遇到的问题和障碍
- **示例**: "安装过程复杂"、"文档不够详细"、"功能难以理解"

#### 7. 机会 (Opportunities)
- **定义**: 改进客户体验的机会
- **示例**: "简化安装流程"、"提供更详细的文档"、"改进用户界面"

### 客户旅程映射的类型

| 类型 | 描述 | 最佳使用场景 |
|------|------|-------------|
| 当前状态映射 | 映射客户当前的体验 | 识别现有问题 |
| 未来状态映射 | 映射理想的客户体验 | 设定改进目标 |
| 服务蓝图 | 映射客户体验和后台流程 | 优化端到端体验 |
| 竞品映射 | 映射客户与竞品的体验 | 识别差异化机会 |

### 客户旅程映射与其他工具的关系

| 工具 | 关注点 | 与 CJM 的关系 |
|------|--------|---------------|
| 客户旅程映射 | 客户体验流程 | 核心框架 |
| 客户访谈 | 客户需求收集 | 输入来源 |
| 数据分析 | 客户行为分析 | 输入来源 |
| 精益画布 | 业务模式 | 战略层面 |
| 机会-解决方案树 | 机会探索 | 补充工具 |
| 问题框架画布 | 问题定义 | 补充工具 |

### 为什么使用客户旅程映射

1. **客户中心**: 从客户角度理解产品体验
2. **全面性**: 涵盖客户与产品互动的全流程
3. **可视化**: 提供直观的可视化分析工具
4. **协作**: 促进团队内部和跨部门的协作
5. **数据驱动**: 基于真实数据和证据进行分析

### 反模式 (Anti-Patterns)

1. **产品中心**: 从产品功能出发，而不是从客户体验出发
2. **过于简化**: 忽略客户体验的复杂性和细节
3. **缺乏数据**: 基于假设进行分析，不使用真实数据
4. **静态映射**: 映射创建后不再更新，无法反映变化
5. **忽略情感**: 只关注行为，忽略客户的情感和想法

## Application / 应用流程

### 第一步: 定义客户角色

明确目标客户的特征和需求：

1. **收集客户数据**: 通过客户访谈、调研、数据分析等收集客户信息
2. **创建客户画像**: 基于数据创建典型的客户角色
3. **验证客户画像**: 通过客户访谈验证客户画像的准确性

**客户画像模板**:
```markdown
## 客户角色: [角色名称]

### 基本信息
- **姓名**: [示例姓名]
- **年龄**: [年龄范围]
- **职位**: [职位]
- **行业**: [行业]
- **公司规模**: [公司规模]

### 需求和目标
- **主要需求**: [需求 1], [需求 2], [需求 3]
- **主要目标**: [目标 1], [目标 2], [目标 3]

### 痛点
- **痛点 1**: [描述]
- **痛点 2**: [描述]
- **痛点 3**: [描述]

### 行为特征
- **使用习惯**: [描述]
- **决策过程**: [描述]
- **信息来源**: [来源 1], [来源 2], [来源 3]
```

### 第二步: 定义旅程阶段

将客户与产品的互动分为不同的阶段：

1. **识别关键阶段**: 基于产品类型和客户行为识别关键阶段
2. **定义阶段目标**: 为每个阶段定义客户的目标
3. **确定阶段边界**: 明确每个阶段的开始和结束

**常见阶段示例** (AIMES CLI):
1. **认知**: 了解 AIMES CLI 的存在和功能
2. **考虑**: 评估 AIMES CLI 是否适合自己的需求
3. **决策**: 决定是否安装和使用 AIMES CLI
4. **安装**: 下载和安装 AIMES CLI
5. **配置**: 配置 AIMES CLI 以适应自己的环境
6. **首次使用**: 使用 AIMES CLI 执行第一个任务
7. **持续使用**: 持续使用 AIMES CLI 进行工程治理
8. **推荐**: 推荐 AIMES CLI 给其他人

### 第三步: 分析每个阶段

在每个阶段中分析客户的行为、想法、感受和痛点：

1. **客户行为**: 客户在该阶段中的具体行为
2. **客户想法**: 客户在该阶段中的想法和问题
3. **客户感受**: 客户在该阶段中的情感状态
4. **痛点**: 客户在该阶段中遇到的问题和障碍
5. **机会**: 改进客户体验的机会

**阶段分析模板**:
```markdown
### 阶段: [阶段名称]

#### 客户行为
- [行为 1]
- [行为 2]
- [行为 3]

#### 客户想法
- "[想法 1]"
- "[想法 2]"
- "[想法 3]"

#### 客户感受
- [感受 1]
- [感受 2]
- [感受 3]

#### 痛点
- **痛点 1**: [描述] - [影响] - [证据]
- **痛点 2**: [描述] - [影响] - [证据]

#### 机会
- **机会 1**: [描述] - [预期影响] - [优先级]
- **机会 2**: [描述] - [预期影响] - [优先级]
```

### 第四步: 识别关键见解

基于分析结果识别关键见解：

1. **关键痛点**: 对客户体验影响最大的痛点
2. **关键机会**: 改进客户体验的最佳机会
3. **关键时刻**: 客户体验的关键转折点
4. **改进优先级**: 基于影响和可行性的改进优先级

### 第五步: 制定行动计划

基于见解制定具体的行动计划：

1. **短期行动**: 快速修复的高影响问题
2. **中期行动**: 需要较多资源的重要改进
3. **长期行动**: 战略性的客户体验改进

## Evidence Labeling System / 证据标签系统

所有分析点必须标注以下标签之一：

- **Fact**: 基于公开可验证的数据、文档或权威来源
  - 示例: 客户访谈记录、使用数据、产品分析数据
- **Inference**: 基于逻辑推理、模式识别或专业判断的合理结论
  - 示例: 基于客户行为模式推断需求、基于产品使用模式推断痛点
- **Assumption**: 基于假设的前提条件，需要进一步验证
  - 示例: 客户会喜欢这个改进、这个改进会提高转化率

**标签使用指南**:
- 优先使用 Fact 标签，基于真实数据
- 明确标注 Inference 的推理过程和依据
- 列出需要验证的 Assumption，并设计验证方法

## Common Pitfalls / 常见陷阱

### 陷阱 1: 产品中心思维
**表现**: 从产品功能出发，而不是从客户体验出发
**解决方案**: 从客户角度重新审视产品
**工具**: 使用客户访谈和观察

### 陷阱 2: 过于简化
**表现**: 忽略客户体验的复杂性和细节
**解决方案**: 深入分析每个阶段的细节
**工具**: 使用详细的分析模板

### 陷阱 3: 缺乏数据
**表现**: 基于假设进行分析，不使用真实数据
**解决方案**: 收集和使用真实的客户数据
**工具**: 使用数据分析和客户访谈

### 陷阱 4: 静态映射
**表现**: 映射创建后不再更新
**解决方案**: 定期回顾和更新映射
**频率**: 每次新的客户数据或产品变化，每月正式回顾

### 陷阱 5: 忽略情感
**表现**: 只关注行为，忽略客户的情感和想法
**解决方案**: 深入分析客户的情感和想法
**工具**: 使用客户访谈和调研

### 陷阱 6: 过度关注问题
**表现**: 只关注痛点，忽略机会
**解决方案**: 平衡分析痛点和机会
**工具**: 使用 SWOT 分析
